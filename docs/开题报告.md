## 一、选题背景与意义

### 1.1 选题背景

检索增强生成(Retrieval-Augmented Generation, RAG)是大语言模型应用最广泛的范式之一。其核心思想是在生成阶段从外部知识库中检索相关文档片段,与问题一同输入 LLM,以缓解幻觉、知识时效性和领域适配问题。

然而,标准 RAG 范式存在一个根本性假设——**"一次检索就够用"**。在多跳问答(Multi-hop QA)、复杂推理、事实核查等任务中,问题的答案往往需要**跨多个文档、经过多步推理**才能得出。标准 RAG 在这些任务上的失败模式已被多项研究指出:**检索失败**(单次检索未覆盖所有必要事实)、**推理失败**(长上下文中难以正确整合)、**幻觉问题**(模型倾向于猜测而非再查一次)。

**Agentic RAG(智能体驱动的 RAG)**正是为解决这些问题而提出的新范式:让 LLM Agent **主动决定何时检索、检索什么、检索几次**,而非被动接受单次检索结果。然而,现有研究存在三个关键不足:**(1) 决策机制不透明**——多数工作只展示最终结果,不分析"为什么这样决策";**(2) 决策质量缺乏量化评估**——研究只报告 EM/F1,不评估决策本身的对错;**(3) 检索步数-准确率 Pareto 关系不明**——多步检索必然更准但延迟更高,何时"够用"不清楚。

### 1.2 选题意义

- **理论意义**:填补"单次检索 vs 迭代检索"决策机制的系统性研究空白,提出"模型规模 × Agent 范式 × 任务类型"三维评估矩阵,揭示决策行为与最终结果的关系。
- **实践意义**:为多跳问答、事实核查、企业知识库问答等场景提供更鲁棒的 RAG 方案,为"何时需要 Agent 决策、何时单次检索就够"提供经验依据。
- **个人发展**:在 RAG / Agent / 决策机制方向积累完整研究经验,为后续深造和工作打下基础。
- **项目联动**:与本人已有 RAG 研究项目形成"基础 RAG → Agentic RAG"的演进证据链,工程上复用现有检索模块,聚焦于决策层研究。

## 二、国内外研究现状

### 2.1 从 RAG 到 Agentic RAG 的演进

RAG 的经典范式由 Lewis 等人(2020)奠基,核心是 DPR + BART 生成 + 单次检索。近三年的演进可划分为三个阶段:

1. **增强型 RAG(Self-RAG、FLARE)**:在生成过程中检测不确定性或检索质量,动态决定是否二次检索。
2. **思维链引导的检索(IRCoT)**:Trivedi 等人(2023)提出在 CoT 每一步自动触发检索,首次实现"推理-检索"的细粒度交织。
3. **Agent 驱动的检索(Self-Ask、ReAct + RAG)**:把 LLM 视为 Agent,主动调用 search/lookup/finish 等动作,完成多步推理与迭代检索。

代表性工作包括:Self-RAG(Asai et al. 2023)、FLARE(Jiang et al. 2023)、IRCoT(Trivedi et al. 2023)、Self-Ask(Press et al. 2023)、ReAct(Yao et al. 2023)。

### 2.2 现有研究的不足

1. 决策机制不透明,缺乏可解释性分析
2. 决策质量缺乏量化评估指标
3. 检索步数-准确率 Pareto 关系不明
4. 任务类型与决策策略的适配性研究稀缺
5. 小模型在 Agentic RAG 上的能力未充分研究

### 2.3 本研究切入点

基于上述空白,本研究聚焦:(1)决策行为可视化与分析;(2)决策质量评估协议;(3)检索步数-准确率 Pareto 曲线;(4)多种 Agent 范式对比;(5)基于已有 RAG 项目的"前 vs 后"对比。

## 三、研究内容与目标

### 3.1 核心研究问题

**主问题**:在多跳问答任务中,LLM Agent 能否学会"何时检索、检索什么、检索几次",以最少的检索步数获得最高的答案准确率?

**子问题**:
- Q1:Agent 检索决策行为与最终答案正确率有何关系?
- Q2:不同 Agent 范式(ReAct / Plan-and-Execute / Self-Ask / IRCoT)对检索决策行为有何影响?
- Q3:检索步数与答案准确率之间是否存在 Pareto 前沿?最优停止时机如何确定?
- Q4:Agentic RAG 与单次 RAG 相比,在多跳问答任务上的提升与成本如何?

### 3.2 研究内容

1. **多跳问答评估基准构建** — 基于 HotpotQA / 2WikiMultihopQA / MuSiQue
2. **Agent 决策行为记录与分析框架** — Thought / Action / Observation 完整记录
3. **多种 Agent 范式的对比实验** — ReAct / Plan-Execute / Self-Ask / IRCoT
4. **Agentic RAG vs 基础 RAG 对比实验** — 量化提升与成本
5. **决策质量评估协议** — 提出"检索决策正确率"等新指标

### 3.3 研究目标

- **学术**:撰写一篇可投稿至 ACL / EMNLP / NLPCC / CCL 等会议的论文
- **工程**:交付完整、可复现的 Agentic RAG 实验平台,代码风格与已有 RAG 项目一致
- **个人**:在 RAG / Agent / 决策机制方向积累完整研究经验

### 3.4 创新点

1. 首次系统对比多种 Agentic RAG 范式在多跳问答上的决策行为与效果
2. 提出"检索决策正确率"指标,将决策质量从最终结果中解耦
3. 系统揭示检索步数-准确率 Pareto 前沿
4. 基于已有 RAG 项目的扩展式研究,形成"基础 RAG → Agentic RAG"的演进证据链

## 四、研究方法与技术路线

### 4.1 整体技术路线

```
        多跳问题 → Agent 决策层 → "检索 / 不检索"决策
                                    │
                                    ├─ 检索 → 生成 query → 基础 RAG 检索器
                                    │       (复用: FAISS + BGE Reranker)
                                    │
                                    └─ 不检索 → 准备回答
                                       │
                                       ▼
                                   Observation → 反思/继续
                                       │
                                       ▼
                                   最终答案生成
```

### 4.2 模块设计

| 模块 | 职责 | 实现位置 |
|------|------|----------|
| Agent 决策层 | 多范式实现(ReAct/Plan-Exec/Self-Ask/IRCoT) | `src/agents/` |
| 基础检索器 | FAISS 检索 + Reranker(复用已有项目) | `src/retrievers/` |
| 动作注册 | Search / Lookup / Finish | `src/actions/` |
| 任务定义 | 多跳问答数据加载与解析 | `src/tasks/` |
| 评估模块 | 答案指标 / 决策指标 / 轨迹记录 | `src/evaluation/` |
| 工程基础 | 配置 / 离线 / 日志(复用已有项目) | `src/utils/` |

### 4.3 数据集

| 数据集 | 用途 | 规模 |
|--------|------|------|
| HotpotQA(distractor) | 主数据集 | 500-1000 样本 |
| 2WikiMultihopQA | 泛化性验证 | 300-500 样本 |
| MuSiQue | 难度分析 | 200-500 样本 |

### 4.4 评估指标

- **答案指标**:EM、Answer F1、Support F1(HotpotQA 官方)
- **决策指标**(本研究新增):检索决策正确率、过度检索率、检索不足率
- **效率指标**:平均检索步数、token 消耗、延迟

### 4.5 实验方案

- **对照组**:无 RAG、单次 RAG、CoT + 单次 RAG
- **实验组**:4 Agent 范式 × 2 检索器 × 4 步数上限 = **32 组实验**
- **消融实验**:移除规划、移除反思、不同 Top-K、不同提示词
- **可视化**:决策行为时间线、检索步数分布、Pareto 曲线、失败模式饼图
