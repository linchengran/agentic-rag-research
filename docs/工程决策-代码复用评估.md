# 工程决策记录:与 rag-research-project 的代码复用评估

日期:2026-10-02 状态:**已决策(不合并,保持独立实现)**

## 背景

README「已知限制」中遗留一项:"与已有 RAG 项目的代码复用尚未实现,目前是独立骨架,后续需要完成 import 适配"。原方案(README §边界):`pip install -e ../rag-research-project` 后 import 复用其 Embedding / FAISS 检索 / BGE Reranker / 配置 / 日志。

## 评估结论(2026-10-02 实测)

1. **原方案不可执行**:`rag-research-project` 没有 `setup.py` / `pyproject.toml`,`pip install -e` 无入口。
2. **顶层包名冲突**:两个项目的代码包都叫 `src`(且双方都有 `src/__init__.py`),同一解释器内 `sys.path` 只能解析到其中一个 `src`,直接 import 必然撞名;需 importlib 以别名加载或先给两项目包化改名。
3. **API 已实质分化**:
   - 对方:扁平结构(`Embedder` / `VectorStore`(内建 MMR)/ `Reranker`),区分 `encode_queries` / `encode_documents`(bge 查询前缀);
   - 本项目:统一 `RerankRetriever`(index_documents / load / save / retrieve),无查询前缀、无 MMR。
4. **语义差异会破坏可比性**:若把检索后端换成对方实现(查询前缀 + MMR),检索行为改变,本项目已完成的全部实验(baseline 500 题、4 范式正式矩阵 n=100、guard 干预、per-step 分析)与新增结果的对照关系失效。

## 决策

- **保持本项目检索器实现为唯一后端(实验代码冻结)**,不为复用而重构。
- 对方项目按其自身定位独立演进;两项目关系从"代码复用"修正为"**方法同源、实现独立**"(同一套 Embedding / Reranker / FAISS 选型与配置约定)。
- 若未来确需合并:前置条件是双方包化(各自改名,如 `ragbase` / `agentrag`)+ 抽出公共检索包;在本项目侧用适配器模式接入,并以现有 n=100 结果做回归校验(同一索引、同一 query 集命中率一致才允许替换)。
